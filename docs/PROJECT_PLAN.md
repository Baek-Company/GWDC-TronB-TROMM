## 1. 아이디어와 해결할 문제

**한 문장:** 사용자의 지출 일정과 위험 성향을 대화로 확인하고, TRON의 JustLend 예치와 USDD 전환·예치 경로를 비용과 출금 위험까지 포함해 비교한 뒤, 사용자가 승인한 거래를 실행하고 예상과 실제 결과를 추적하는 AI 자산 운용 도우미입니다.

대상은 TRON에서 USDT 등 스테이블코인을 보유하면서 가까운 시일에 일부를 지출해야 하는 사용자입니다. 연간 수익률 숫자만 보고 예치하면, 짧은 운용 기간에는 거래비용이 이자를 넘거나 지출일에 필요한 금액을 꺼내지 못할 수 있습니다. 제품은 **지출일에 쓸 돈을 먼저 확보하고, 남은 돈의 출금 후 순수익을 비교**합니다.

제출판의 성공 조건은 사용자가 같은 조건에서 두 경로의 예상 결과와 제약을 이해하고, **선택한 계획과 같은 체인·자산의 거래**를 명시적으로 승인하며, 그 포지션의 이후 결과를 검토할 수 있는 것입니다. 수익률과 실제 수익은 보장하지 않습니다.

JustLend는 이미 시장 분석, 포트폴리오 조회, 예치·인출과 비용 추정 기능을 갖춘 [공식 AI 도구](https://docs.justlend.org/ai_support/mcp_server/)를 제공합니다. 따라서 이 프로젝트는 **지출 날짜별 필요 금액, 출금까지의 왕복 비용, 거래 보류 판단**이 추천을 실제로 바꾸는 장면을 보여주어야 합니다.

## 2. 제출판 범위와 현재 상태

| 대회 기준 | 제출판 완료 조건 | 현재 상태 |
| --- | --- | --- |
| 요구 분석 | 보유 자산·금액, 지출 날짜/금액, 운용 기간, 위험 성향을 대화로 수집하고 누락 항목을 다시 질문한 뒤 요약 확인 | 기본 `profileSchema`와 가상 사례만 있음. 날짜별 지출 입력·확인 흐름 없음 |
| TRON 생태계 | JustLend와 USDD의 **독립적인** 데이터/계약 경로, 적용 조건, 출처 URL, 체인, 조회 시각 표시 | JustLend Mainnet 시장 GET 연결. USDD 독립 어댑터 없음 |
| 계획·수익 추정 | 같은 시작 자산과 기간으로 실행 가능성을 검증한 최소 두 계획. 배분, 기본 수익, 조건부 보상, 진입·출구 비용, 출금 조건, 위험을 각각 표시 | Decimal 기반 단일 수익 계산 유틸만 있음 |
| 실행·관리 | 거래마다 금액·대상 계약·체인·수수료 상한·위험·승인 범위를 보여주고 사용자 확인 후 지갑 서명. txID와 확정 결과 기록 | TronLink 주소 연결만 있음. 거래 기능 없음 |
| 추적·검토 | 원래 계획과 계산 가정 보존, 이후 자산·수익 관측, 예상과 실제 비교. 재생 자료는 화면에 표시 | 시장 스냅샷 명령만 있음. 사용자 포지션 추적 없음 |

위 완료 조건은 사용자님이 제공한 [대회 원본 PDF](references/tron-challenge-brief.pdf)의 Challenge B(2쪽)를 기준으로 이 문서에 직접 정리했습니다. 현재 상태는 저장소의 실제 구현을 확인한 결과입니다. 대회 원문은 사후 **검토 화면**에 과거 재생 또는 가상 포지션을 허용합니다. 실제 거래 실행을 했다고 표시할 때에는 해당 체인의 원 txID와 확정 결과가 필요합니다.

### 이번 제출의 우선순위

1. **P0 · 최우선:** 한 체인·자산에서 요구 분석 → 계획 선택 → 승인 → 예치 또는 인출 → txID 확정 → 같은 포지션 재조회의 최소 흐름을 먼저 완성합니다.
2. **P0:** JustLend와 USDD의 별도 근거를 연결하고, 같은 시작 자산·기간의 **실행 가능한** 계획 두 개와 보유 기준선을 비용·출구까지 비교합니다. 확인 불가능한 경로는 실행 가능 계획에서 제외합니다.
3. **P0:** 지출 날짜/금액을 바꾸면 투자 가능액 또는 권고가 바뀌는 것을 시연합니다. 비용 초과 시 거래 보류를 실제 결과로 반환합니다.
4. **P1:** 예치와 인출을 모두 시연하고, 변동 조건에 따른 재계산·조정 제안 및 예상/실제 비교를 보여줍니다. 재생 자료는 전체 구간에 표시합니다.
5. **공통:** 모든 금액과 데이터에 자산 단위·체인·출처·조회 시각·실데이터/과거/가상 구분을 붙입니다.
6. **제출 후:** 여러 사용자군, 추가 프로토콜, 자동 재배분, 유료화 기능을 검증합니다.

## 3. 고정 시연 사례와 사용자 흐름

가상 사용자: **1,000 USDT 보유, 30일 운용, 7일 뒤 200 USDT 지출, 추가 비상 예비액 0 USDT, 균형형 위험 성향**. 사용자가 지출 날짜나 금액을 빠뜨리면 에이전트가 먼저 묻고, USDD 경로를 보여주기 전에 가격 변동 위험을 받아들일지 확인합니다. 이 금액은 시연 입력이며 실제 사용자 잔고나 현재 금리를 뜻하지 않습니다.

**일정 변화 시연:** 1,000 USDT 중 예정 지출 200 USDT는 지출일이 7일 뒤든 운용 종료 이후인 45일 뒤든 현재 가정 화면에서 보호합니다. 따라서 전 기간 운용 상한은 두 경우 모두 800 USDT입니다. 날짜를 앞당기면 회수 기한과 비용·유동성 검증 조건이 달라집니다. 45일 지출금을 30일간 운용하려면 30일 종료 시점의 환매·수령액·비용 근거가 별도로 검증되어야 하며, 현재 합성 5% 사례는 이를 충족하지 않습니다.

**별도 Nile 거래 사례:** 100 테스트 TRX 보유, 30일 계획, 20 TRX 유동성 확보를 가정합니다. `80 TRX 예치 + 20 TRX 보유`와 `50 TRX 예치 + 50 TRX 보유`를 Nile jTRX 계약의 읽기값으로 비교하고 한 계획을 선택해 거래·포지션 조회를 시연합니다. 비용 때문에 순익이 음수라면 `개발자 테스트 실행`으로만 진행하며 경제적으로 유리한 추천이라고 설명하지 않습니다. 테스트 토큰의 수익은 실제 USDT 수익으로 환산하지 않으며, 이 사례는 Mainnet의 USDD 경로 실행을 입증하지 않습니다.

1. 사용자가 보유 자산·금액과 예정 지출을 입력합니다.
2. 에이전트가 운용 종료일, 지출 날짜, 남겨야 할 금액, 위험 선호 중 빠진 항목을 질문합니다.
3. 사용자가 요구사항 요약을 확인합니다. 확인 전에는 계획을 확정하지 않습니다.
4. 서버가 JustLend 시장·보상 및 USDD PSM 조건을 조회하고, 출처·체인·조회 시각을 표시합니다.
5. 같은 1,000 USDT와 30일을 기준으로 계획 A/B 및 전액 보유 기준선을 보여줍니다. 기본 이자·조건부 보상·왕복 비용·예상 순수익·손익분기 기간을 한 표에서 비교합니다.
6. 사용자가 계획을 선택하면 거래 단계별 금액·비용·위험·승인 범위를 다시 확인합니다.
7. 지갑이 서명한 거래의 txID, 제출/확정/실패 상태와 체인 관측값을 기록합니다.
8. 지출 날짜를 변경해 계획이 달라지는 이유를 설명하고, 필요하면 별도 승인 후 조정 거래를 돕습니다.
9. 원래 예상과 이후 실제 관측을 비교합니다. 재생 자료를 쓰면 해당 구간 전체에 `시뮬레이션` 배지를 표시합니다.

## 4. 계획 생성 알고리즘

### 후보 계획

| 계획 | 자금 흐름 | 출구 | 비교할 핵심 위험 |
| --- | --- | --- | --- |
| A. USDT 예치 | 200 USDT 보유 + 800 USDT를 활성 JustLend jUSDT 시장에 예치 | jUSDT 인출 → USDT | 시장의 인출 가능 유동성, 금리 변동, 계약 위험 |
| B. USDD 경로 | 200 USDT 보유 + 800 USDT를 USDD PSM에서 전환 → 활성 JustLend jUSDD 시장에 예치 | jUSDD 인출 → USDD PSM에서 USDT 전환 | USDD 가격 변동, PSM 출구 물량, 추가 거래비용과 계약 위험 |
| 기준선 | 1,000 USDT 보유 | 필요할 때 사용 | 예치 수익 없음 |

두 토큰의 공식 배포 주소가 같은 경로를 가리키는지와 각 시장의 활성 상태를 **거래 직전에 재검증**합니다. 최신 [USDD 배포 주소 Markdown 원문](https://docs.usdd.io/developers/deployment-addresses.md)과 [JustLend 배포 계약](https://docs.justlend.org/developers/deployed_contracts/)은 모두 `TXDk8mbtRbXeYuMNS83CfKPaYYT8XWv9Hz`를 기재하지만, 오래된 웹 색인에는 다른 USDD 주소가 남아 있습니다. 정적 문서의 일치만으로 PSM 출력·출구를 보증하지 않으므로 PSM 출력 토큰, jUSDD `underlying()` 및 필요할 수 있는 마이그레이션 경로를 온체인에서 확인하기 전에는 계획 B를 실행 가능한 경로로 분류하지 않습니다. [USDD PSM](https://docs.usdd.io/user-guide/psm-peg-stability-module)

PSM은 **전환 경로**입니다. 계획 B의 예치 이자는 JustLend jUSDD 시장에서 생기며, PSM 자체의 수익률을 더하지 않습니다. USDD 경로의 계약·물량·왕복 비용이 확인되지 않으면 계획 B를 실행 가능한 계획으로 세지 않습니다.

### 계산과 판정

- 지출을 `날짜·금액·지급 자산`으로 저장합니다. 각 지출일의 예상 보유액에서 그날까지의 지출액과 사용자 지정 예비액을 빼서 부족한 시점을 찾습니다. 정해진 날짜에 출금·전환을 마칠 수 있는지와 그 비용도 검사합니다. 만족하지 못하면 예치액을 줄이거나 계획을 제외합니다.
- 위험 선호를 허용 자산·가격 변동 위험·최대 배분 비율에 적용합니다. 보수형 사용자가 USDD 위험을 허용하지 않았다면 B를 추천 후보에서 제외하고 이유를 설명합니다. 균형형 사용자에게도 디페깅·PSM 출구 위험을 별도로 확인받습니다.
- 각 경로의 **기본 이자**는 해당 시장의 APY와 기간으로 계산합니다. **추가 보상**은 자격·지급 자산·기간·청구 조건을 확인한 경우에만 별도로 추정합니다. 미확인 보상은 `미확인`으로 표시합니다.
- 비용에는 승인, 전환, 예치, 인출, 재전환, 보상 청구에 필요한 TRON Energy/Bandwidth 비용을 포함합니다. TRX 비용을 USDT로 환산할 근거가 없으면 순수익을 확정 수치로 제시하지 않습니다.
- `예상 순수익 = 기본 수익 + 검증된 추가 보상 − 진입·보유·출구 비용`으로 표시합니다. 같은 자산으로 평가하려면 USDD→USDT의 정상 전환 가능성을 가정했음을 적고, USDD 가치 변화와 전환 불가 상황을 별도 스트레스 시나리오로 보여줍니다. 수익률은 조회 당시 값이 운용 기간 내내 유지된다는 **가정**입니다.
- 고정 금리·비용 **가정 아래의** 손익분기 기간과 최소 운용액을 추정해 `예상 수익 > 왕복 비용`이 성립하는 범위를 표시합니다. 확정 임계값처럼 표현하지 않습니다. 비용·환산 시각·가용량 중 하나라도 확인되지 않으면 순수익 순위와 실행 권고를 보류합니다.
- 활성 계약, 자산 정밀도, 지갑 잔고, PSM 가용량, 시장 인출 유동성, 지출일 제약을 통과한 경로만 `실행 가능`으로 표시합니다. 비용이 이익을 넘으면 그 결과와 전액 보유 기준선을 그대로 보여줍니다.
- 금액은 문자열과 Decimal/BigInt로 처리합니다. LLM은 질문과 설명을 맡고, 금액 계산·계약 적격성·거래 생성은 검증된 코드가 결정합니다.

첫 구현은 [기존 계산 유틸](../shared/planning.ts)과 [정밀 단위 변환](../shared/markets.ts)을 확장합니다. 현재 계산 함수의 `totalCost`는 같은 자산으로 환산된 입력이므로, TRX 비용의 환산 근거와 시점을 별도로 기록해야 합니다.

**수익성 검증용 예시:** 운용액 800 USDT, 30일, 연 5% APY를 순전히 설명용으로 가정하면 기본 이자는 약 **3.21 USDT**입니다. 현재 상품 금리가 아니며 전환·거래비용 전 값입니다. 실제 왕복 비용이 이보다 크다면 에이전트는 해당 운용을 권하지 않아야 합니다.

### AI 대화

- 서버에서 모델 API를 호출해 사용자 입력을 구조화하고 빠진 조건을 묻습니다. 모델 응답은 스키마 검증 후 사용합니다.
- 설명에는 채택한 수치의 출처와 가정을 연결합니다. 검증되지 않은 금리·거래비용·계약 주소를 모델이 만들어 내면 계획에 반영하지 않습니다.
- AI API 사용은 가능하지만 **키는 아직 전달받지 못한 상태**입니다. 모델 인터페이스와 스키마 검증은 키 없이 먼저 만들고, 9월 29일 09:00까지 실제 키 연결 여부를 결정합니다. 키는 서버 환경의 `.env.local`에만 두고 화면·Git·로그에 노출하지 않습니다.
- 모델 연결 시 자유 문장 입력, 누락된 지출 날짜 질문, 변경된 지출일에 따른 설명을 고정 사례 3개로 확인합니다. 키가 없으면 정해진 질문과 설명 템플릿으로 기본 흐름을 제공하고, **AI 항목이 부분 구현임을** 발표에서 밝힙니다. 로컬 모델 검토는 2시간 이내로 제한합니다.

### 거래와 추적

- **첫 기술 게이트:** 시연할 지갑·자산·체인에서 실제 계약과 테스트 잔고가 있는지 확인하고, 그 체인에서 계획 선택부터 포지션 재조회까지 연결할 수 있는 경로를 고릅니다.
- 기본 테스트 경로는 **Nile의 JustLend V1 jTRX 소액 계획 → 예치 → txID → 포지션 재조회 → 인출**입니다. 공식 계약 목록과 온체인 코드·상태를 확인한 뒤 진행합니다. Nile USDT 테스트 자산을 확보하면 같은 자산의 jUSDT 경로를 검토합니다.
- Mainnet의 USDT·USDD 계획 비교와 Nile 실행은 서로 다른 시연입니다. **Mainnet 예상 APY를 Nile 거래의 실제 수익으로 합산하지 않습니다.** 자발적으로 준비된 Mainnet 소액 자산과 명시적 거래 승인까지 갖춘 경우에만 Mainnet 계획 중 한 개의 실제 실행을 추가 검증합니다.
- 매 거래 전에 체인, 토큰, 금액, 대상 계약, 필요한 승인 범위(네이티브 TRX라면 없음), 비용 추정/상한, 주요 위험을 보여줍니다. 사용자 확인 이후 TronLink 서명을 요청합니다. 승인과 예치가 각각 필요한 자산이면 각각의 확인을 받습니다.
- 방송 응답만으로 성공 처리하지 않습니다. 원 txID를 조회해 확정 영수증·실패 사유·실제 비용을 저장합니다. 타임아웃 시 먼저 같은 txID를 조회해 중복 거래를 막습니다. [TRON 거래 확정 기준](https://developers.tron.network/docs/confirmation-semantics)
- 계획 입력·사용한 금리·비용 가정·데이터 시각·선택 이유와 txID를 저장합니다. 제출판에서는 비밀 정보 없이 브라우저 로컬 저장소에 계획 메타데이터를 보관하고, 잔고·거래 상태는 체인에서 다시 읽습니다.
- 예정 지출과 실제 지출은 **외부 현금흐름**으로 별도 기록합니다. 유동성 200 USDT를 지출했을 때 이를 투자 손실로 계산하지 않습니다. 투자 성과에는 예치·인출 원금, 실제 비용, 보상과 현재 포지션 가치만 반영합니다.
- 장기 성과 화면은 실제 관측값 또는 명확히 표시한 과거 재생/가상 포지션으로 구현합니다. 재생 수익을 실제 계정 수익으로 표시하지 않습니다.
- 새 금리·인출 유동성·예정 지출을 읽으면 원계획과 비교해 변경 제안을 만듭니다. 제안에는 추가 수익에서 재배분 비용을 뺀 값과 새 출금 위험을 적고, 별도 사용자 승인 전에는 거래하지 않습니다.

**평가상 남는 격차:** Mainnet의 A/B 계획 비교와 Nile jTRX 소액 거래만 완료되면 거래 기술은 증명할 수 있어도, 선택한 Mainnet 계획이 그대로 실행됐다는 증거는 아닙니다. Nile에는 별도의 Nile 금리·잔고를 사용한 계획 스냅샷을 만들어 같은 Nile 포지션의 거래·추적을 시연합니다. 그래도 **Mainnet USDT·USDD 계획 전체의 실행 기준은 부분 구현**입니다. 제출물과 발표에 이를 명시합니다.
