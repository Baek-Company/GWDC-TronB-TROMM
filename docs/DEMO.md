# LeeMir 로컬 시연 · Nile 우선 대본

이 대본은 사용자님의 **Nile 테스트넷 중심 시연** 결정에 맞춘 화면 순서입니다. 거래의 실제 적용·검증 상태는 [구현 상태](./IMPLEMENTATION_STATUS.md)를 확인합니다. 아래 입력 금액과 USDT 이자는 시연용 가정이며 실제 수익이나 거래 권고가 아닙니다. [프로젝트 원계획](./PROJECT_PLAN.md)은 Nile TRX 거래 사례와 Mainnet USDT 계획 사례를 서로 다른 체인·자산으로 분리합니다.

## 1. 첫 화면: Nile TRX·jTRX 계획

1. `./scripts/run run dev`로 시작해 첫 화면 `/`(`/nile`도 동일)에서 **Nile 테스트넷 시연** 표시와 지갑 체인을 확인합니다. TronLink가 Nile이 아니면 Nile 잔액·계획·거래 화면에 Mainnet 값을 섞지 않습니다. [TRON TronLink 연동 안내](https://developers.tron.network/docs/tronlink-integration)는 Nile을 별도 체인으로 구분합니다.
2. 새 세션의 기본 예시 **가상 100 테스트 TRX**, **7일 뒤 지출 20 테스트 TRX**, 운용 가능 상한 **80 테스트 TRX**를 확인합니다. Nile 화면에서 날짜별 지출을 최대 10건까지 추가할 수 있습니다. 이전 버전에서 저장된 조건은 새 형식으로 옮기고 재확인을 요구합니다. 지출액을 바꾸거나 지출을 추가하면 보호분과 운용 상한이 다시 계산됩니다. 날짜 변경은 회수 기한과 계획 확인 버전을 바꿉니다.
3. 지갑에서 Nile 주소를 연결하고 입력 요약을 확인한 뒤 Nile 계획을 조회합니다. 수수료 재원 등으로 상한이 더 줄지 않은 기본 사례에서는 `80/20`·`50/50` 후보의 예치액이 각각 80·50 TRX이며, 7일 뒤 지출액은 보호된 상태로 설명합니다. 가상 입력과 지갑에서 관측한 테스트 TRX 잔액은 별도로 표시합니다.
4. Nile jTRX의 시장 상태·금리·잔고·조회 시각이 실제로 읽힌 경우에만 이를 **Nile 관측값**이라고 설명합니다. 읽지 못하면 가정 계산과 오류 사유를 보여주고 실제 상품 수익으로 표현하지 않습니다. JustLend는 [Nile 배포 안내](https://docs.justlend.org/developers/deployed_contracts/)에서 일부 계약이 시험용 자리표시자일 수 있다고 경고합니다.
5. 거래 시연 전 로컬 `.env.local`의 `GWDC_APPROVAL_LEDGER_KEY_HEX`를 설정하고 새 API 프로세스의 `/api/health`에서 `nileApprovalLedgerReady:true`를 확인합니다. 키가 없거나 원장을 열 수 없으면 승인 API가 거래를 중단합니다. 이 값은 **서버 원장 준비 상태**이며 지갑 연결이나 거래 성공을 뜻하지 않습니다. [설정 방법](../README.md#설정과-안전-경계)을 따릅니다.
6. 지갑과 테스트 자산이 준비된 경우, **새 예치 미리보기**에서 Nile 계정·jTRX 계약·예치액·예상/최대 수수료·만료 시각·위험을 확인합니다. 앱의 확인 화면을 진행하면 TronLink에서 먼저 **지갑 소유 확인 메시지**에 서명해 10분짜리 계정 연결 승인 세션을 만듭니다. 메시지 서명은 거래 승인이 아닙니다. 서버는 확인한 지출·예비액 JSON과 최신 Nile 견적·실잔액으로 보호액과 예치액을 다시 계산하고 거래 의도를 예약합니다. 값이 달라졌다면 미리보기를 다시 확인합니다.
7. 사용자님이 TronLink의 **별도 거래 서명** 화면에서 계정·대상 계약·금액·최대 수수료를 확인해 직접 승인합니다. 서버가 같은 서명 거래의 원 txID와 원문을 암호화 원장에 먼저 접수한 경우에만 브라우저가 그 원문을 Nile에 제출합니다. 방송 수락 뒤에도 `pending` 또는 `unknown`일 수 있습니다. 원 txID의 solidified `SUCCESS` 영수증, 실제 수수료, 같은 계정·jTRX 포지션의 예치 전후 증가를 확인해야 예치 성공으로 설명합니다.
8. 확정된 **같은 서버 예치 의도**와 현재 jTRX 잔고가 확인된 경우에만 환매 미리보기를 진행합니다. 환율·시장 현금·모의 실행·수수료를 새로 확인하고 환매의 별도 메시지 인증·거래 확인·TronLink 서명·원 txID를 기록합니다. solidified `SUCCESS`, jTRX 잔고 감소, 해당 원 txID의 계약→지갑 TRX 내부 송금과 실제 수수료가 확인되기 전에는 환매 성공이나 실제 손익을 발표하지 않습니다.
9. 새로고침·API 재시작·응답 유실 뒤에는 첫 화면의 **`서버 미해결 거래 확인·복구`**를 사용합니다. `reserved`인 **서명 전 예약**만 서버 취소 결과를 확인한 뒤 새 미리보기로 진행할 수 있습니다. `signed`·`broadcasting`·`pending`·`unknown`에는 새 서명/재방송을 하지 않고 서버가 보관한 **같은 원 txID**를 조회합니다. 복구 화면의 계정·계획·계약·금액과 브라우저 기록이 일치하지 않으면 거래를 멈추고 근거를 대조합니다.

2026-09-29 16:18 UTC의 읽기 전용 기록에서는 시험 전용 Nile 주소의 **1,000 테스트 TRX**와 예치 전 jTRX 잔고 `0`을 읽었습니다. 이후 사용자님이 **1 TRX 예치와 전체 89.46435499 jTRX 환매를 각각 승인**했고, 같은 지갑의 jTRX 잔고 `0 → 89.46435499 → 0`, 환매 영수증의 실제 수령 `1 TRX`를 확인했습니다. 미리보기의 당시 예상 수수료는 재사용 가능한 견적이 아닙니다. 실제 수수료와 두 원 거래 ID는 [실증 증거 기록](NILE_A_EVIDENCE.md)을 참조해 주세요.

Nile 시험 토큰은 실제 금융 가치를 뜻하지 않습니다. 테스트 TRX·USDT 확보 방법과 시험 전용 지갑 사용 권고는 [TRON 테스트 토큰 안내](https://developers.tron.network/docs/getting-testnet-tokens-on-tron)를 따릅니다. 현재 실거래 완료 여부는 [구현 상태](./IMPLEMENTATION_STATUS.md)에 따로 기록합니다.

## 2. Nile PSM 단독 전환

1. 첫 화면의 **PSM 시험거래**에서 PSM 전용 USDD·USDT 계약 주소와 잔고를 확인합니다. TronLink가 Nile이 아니거나 두 입력 토큰 잔고가 0이면 거래를 시작하지 않습니다. 같은 `USDD` 이름의 다른 계약 토큰은 잔고에 포함되지 않습니다.
2. PSM용 USDD가 준비된 경우 1 USDT 시험 수량을 입력하고 `USDD 사용 승인`의 최신 미리보기에서 승인 대상 PSM 계약과 필요한 USDD·최대 TRX 비용을 확인합니다. 사용자님의 TronLink 거래 서명 뒤 원 txID의 solidified 영수증과 정확한 허용액 재조회를 기다립니다.
3. `USDD → USDT 전환`을 별도로 미리보기·확인·서명합니다. USDD 지출과 USDT 수령이 원시 정수 견적에 맞게 재조회된 후에만 다음 방향으로 진행합니다. 다시 `USDT 사용 승인`의 대상이 **GemJoin**인지 확인하고 확정한 뒤 `USDT → USDD 전환`을 별도 서명합니다.
4. 각 단계가 불명확하면 **미해결 거래 확인·복구**에서 원 txID를 조회합니다. 서명 뒤에는 재방송이나 다음 단계 자동 서명을 하지 않습니다. PSM 출력을 Nile jUSDD 예치 성공으로 표시하지 않습니다.

2026-09-30 기준 시험 지갑의 회색 USDD 2,000은 PSM USDD와 다른 계약의 토큰입니다. PSM용 USDD와 USDT의 실제 잔고는 모두 0이므로 위 거래 단계는 아직 실증되지 않았습니다. 온체인 주소·입금 txID와 검증 경계는 [PSM 계획·증거](NILE_PSM_EXECUTION.md)에 기록했습니다.

## 3. 보조 화면: Mainnet USDT 가상 예상 결과

1. `/usdt-demo`에서 예시 **1,000 USDT**와 예정 지출 **200 USDT**를 확인합니다. `/needs`에서 입력을 수정한 뒤 `/plans`로 가면 지출 보호분을 뺀 운용 가정액 **800 USDT**를 확인할 수 있습니다. 이 금액은 **synthetic 입력**이며 Mainnet 지갑 실잔액 검증을 시연 조건으로 삼지 않습니다.
2. `/usdt-demo`와 `/plans`는 **연 5% APY를 가정**한 비용 전 기본 이자만 보여줍니다. 800 USDT를 30일 운용한다는 가정이면 `800 × ((1 + 0.05)^(30/365) − 1) ≈ 3.21 USDT`입니다. 5%는 조회된 JustLend 금리가 아닙니다.
3. 승인·예치·환매 및 네트워크 비용, 지급일 출구와 순이익은 **미확인**으로 표시합니다. `3.21 USDT`를 순이익·실현 수익·실행 가능한 추천으로 설명하지 않습니다. Mainnet의 실행 적격성은 `false`이며 거래·서명하지 않습니다.
4. 지출 날짜를 7일 뒤에서 45일 뒤로 바꿔도 200 USDT는 계속 보호되어 운용 상한은 800 USDT임을 확인합니다. 지출액이나 지출 건수를 바꾸면 보호액이 바뀝니다. `/markets`의 Mainnet 시장 조회값은 별도 자료이며, synthetic 5% 사례의 근거 또는 Nile 거래의 수익률이 아닙니다.

## 4. 실패·기록 시연

- Nile 지갑 미연결, 체인 전환, 계약·시장 읽기 실패, 테스트 TRX 부족, 수수료·출구 근거 부족은 각 원인으로 표시합니다. 가정 입력을 실잔액으로 대체하지 않습니다.
- `/review`의 세션 JSON 내보내기와 과거(`snapshot`)·가상(`synthetic`) 자료 재생은 읽기 전용입니다. 원 계획과 거래 관측을 같은 체인·자산에서만 비교합니다.
- Mainnet API 장애나 자료 부족이 생겨도 synthetic 5%를 실시간 시세로 대체 표기하지 않습니다. 거래 제출 뒤 상태가 불명확하면 원 txID부터 조회하며 중복 거래를 만들지 않습니다.
- 이번 시연 범위는 사용자님이 직접 서명하는 **Nile 승인형 A**입니다. 브라우저가 닫힌 뒤 무인 거래를 하는 B-1, 금고 B-2, Mainnet 실제 USDT 거래는 이 대본의 실행 단계가 아닙니다.

코드 검사는 `./scripts/run run check`입니다. `./scripts/run run doctor`는 선택적인 외부 원천 진단이며 Mainnet도 조회하므로 이번 가정 시연의 필수 단계가 아닙니다. 테스트·빌드 통과만으로 Nile 실제 예치·환매 성공이나 Mainnet 거래 가능성이 증명되지는 않습니다.
