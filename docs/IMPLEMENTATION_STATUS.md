## 확인 명령과 해석

- 범위 표시: `/api/health`와 `/api/capabilities`의 `mainnetExecution:false`는 Mainnet 거래 경로가 없음을 뜻합니다. `nileExperimentalExecution:true`는 Nile 미리보기·시험 서명 코드 경로가 있음을 뜻하며 실제 성공을 보장하지 않습니다. 서버가 브라우저 지갑·선택 체인을 단독으로 알 수 없으므로 `nileWalletReady`와 `nileChainReady`는 `null`이고 각 동작에서 확인합니다. 이전 `executionEnabled:false`는 호환용 Mainnet 범위 표시입니다.
- 2026-09-29 감사 수정 환경에서 `doctor` 재실행: `ready` 3개(Node 24, NIM 키 설정, 모델 ID), `unavailable` 17개, `unknown` 2개였습니다. 이 터미널의 공식 REST/RPC/MCP 호스트 DNS 조회가 실패하여 외부 상태를 새로 실증하지 못했습니다. NIM 모델 실제 응답도 `doctor`가 검사하지 않습니다.
- 같은 날 네트워크 허용 환경에서 `doctor`를 재실행하면 `ready` 10개, `unavailable` 8개, `unknown` 4개였습니다. JustLend REST 24개 시장, Nile 블록·jTRX 코드/활성 시장/금리, TronGrid MCP 목록·읽기는 준비 상태로 확인했습니다. Mainnet PSM 계약 코드 확인은 실패했고 Stake 2.0은 HTTP 429였습니다. Nile 지갑 잔고·선택 금액의 수수료 재원, SUN.io 입출구 경로는 여전히 미확인입니다. 이는 실제 Nile 거래·Mainnet 실행 가능한 A/B 두 경로를 입증하지 않습니다.
- `doctor` 자체는 NIM 응답을 검사하지 않습니다. 별도 서버 측 최소 요청에서 NIM HTTP 200과 본문 존재를 확인하고, 앱 `analyzeConversation`에서 `provider=nim`·금액/지출일 추출·다음 질문을 확인했습니다. 키 값과 원 모델 응답 본문은 출력하거나 저장하지 않았습니다.
- 배포 파일 크기: 장식 PNG 원본 두 개(약 2.7MB)를 화면에서는 WebP 두 개(합계 약 245KB)로 대체했습니다. 같은 작업 트리의 분할 전 빌드에서 초기 JS는 1,402.93KB(gzip 380.53KB), 경로별 동적 로드 후 335.49KB(gzip 107.15KB)였습니다. Nile 화면의 약 942KB JS는 Nile 경로를 열 때 로드됩니다. 실제 모바일/데스크톱 로딩 시간은 아직 비교하지 않았습니다.

## 신규 예치 보류 진단 · 2026-09-29

첫 네트워크 허용 환경 조회에서는 JustLend jUSDT·jUSDD의 온체인 계약 확인 요청이 **HTTP 429**로 실패해 두 견적 모두 생성되지 않았습니다. 당시 `TRONGRID_API_KEY`는 미설정이었습니다. 키 값은 문서나 UI에 기록하지 않습니다.

429가 해소되어도 보류가 자동으로 해제되지는 않습니다. 현재 jUSDT 견적의 승인·예치·환매·네트워크 비용은 미확인이고 JustLend V1 REST 값에는 출처 갱신 시각이 없어 최신성 조건을 통과하지 못합니다. Mainnet B 경로는 PSM 양방향 환율·가용량과 비용도 확인해야 합니다. 사용자가 연결한 Mainnet TronLink 주소의 동일 자산 실잔액, 보호할 지출액·예비액, 선택 경로의 회수 유동성을 함께 검증해야 합니다. 이 정보를 채운 뒤에도 운용 만기까지 계산한 순이익이 0 이하이거나 지출일 이전 회수가 불가능하면 보류가 올바른 결과입니다. Nile 데이터는 Mainnet 계획의 근거로 대체하지 않습니다.

목표 감시 UI에 보류 사유와 다음 확인 방법을 추가하고, 선택하지 않은 상품의 장애는 선택 경로의 보류 근거에 섞지 않도록 했습니다. 가상 시연 기준선은 실거래 권고로 표시되지 않게 고정했습니다. 별도 로컬 브라우저에서 429 사유와 지갑·견적 미확인 안내를 확인했습니다. **이번 `./scripts/run run check`는 28개 테스트 파일의 235개 테스트, TypeScript 검사와 Vite 빌드가 통과했습니다.** 데이터 원천·비용 어댑터와 Mainnet 실행 경로는 아직 구현·실증되지 않았습니다.

## TronGrid 키 설정 후 재확인 · 2026-09-29

사용자 계정의 무료 TronGrid 콘솔에서 `GWDCLeeMirLocalDev` 개발용 키를 발급했습니다. 키 값은 출력·커밋하지 않았고, Git 무시 대상인 로컬 `.env.local`의 `TRONGRID_API_KEY` 항목에만 저장했습니다. 파일 권한은 `600`입니다. API 서버를 재시작한 뒤 `./scripts/run run doctor`에서 키 설정이 `ready`로 바뀌었습니다(전체 `ready` 11개, `unavailable` 7개, `unknown` 4개).

새 키를 사용한 직접 Mainnet 조회에서 jUSDT 견적이 생성됐고 해당 경로의 HTTP 429는 재현되지 않았습니다. 재시작된 로컬 API의 `/api/plans`도 읽기 전용 가상 조건에 HTTP 200, jUSDT 견적 있음, jUSDT HTTP 429 진단 없음으로 응답했습니다. jUSDD 견적과 PSM 경로는 여전히 미확인이며, jUSDT 견적의 출처 갱신 시각과 왕복 비용도 미확인입니다. 따라서 키 연결 성공을 신규 예치 가능 판정이나 실제 거래 성공으로 해석하지 않습니다.

Mainnet jUSDT의 주소·금액·지출일별 읽기 전용 견적과 검증 순서는 [금액별 실견적 구현 계획](MAINNET_JUSDT_AMOUNT_QUOTE_PLAN.md)에 정리했습니다. 코드·공식 문서 대조에서 찾은 수정점과 외부 확인 게이트는 [계획 검증 결과](MAINNET_JUSDT_AMOUNT_QUOTE_PLAN_VALIDATION.md)에 기록했습니다. 두 파일은 계획·검토 문서이며, 비용 어댑터 구현 또는 Mainnet 실거래 실증을 완료했다는 뜻은 아닙니다.

## Nile 우선 시연·Mainnet 가정 계산 전환 · 2026-09-30

사용자님 결정에 따라 **`/`과 `/nile`을 Nile 테스트넷 TRX·jTRX의 첫 화면**으로 전환했습니다. 이 화면은 지갑 네트워크·Nile 블록·브라우저에 저장된 거래 근거를 구분하고, 지출 날짜·금액을 입력해 보호액과 운용 상한을 계산합니다. 새 세션의 기본 예시는 100 TRX, 7일 뒤 지출 20 TRX, 별도 예비액 0입니다. 이전 `gwdc-nile-needs-v1` 저장 입력에는 지출 항목이 없으므로 기존 금액·기간·예비액을 보존하고 지출 0으로 옮긴 뒤 재확인을 요구합니다. `7일 뒤 20 TRX 예시 지출 적용` 버튼으로 예시를 명시적으로 선택할 수 있습니다.

## Nile 지출·거래 안전성 및 UI 재점검 · 2026-09-30

- Nile 시연 입력은 최대 10건의 날짜별 TRX 지출을 보호합니다. v1·v2 저장 입력은 v3로 옮기고 재확인을 요구합니다. 저장이 실패하면 재시도 안내와 함께 계획·미리보기·서명을 차단합니다. 한국시간 날짜 변경 시 입력 확인과 미리보기를 무효화하며, 거래 구성 후 TronLink 서명 직전에 날짜와 저장 입력을 다시 확인합니다.
- 같은 Nile 지갑의 예치·환매는 계획이 달라도 하나의 브라우저 탭 간 잠금을 사용합니다. 미확정 원 거래가 있거나 저장 근거가 손상되면 새 서명을 차단합니다. 거래 방송만으로 확정 처리하지 않습니다.
